## 三、P1 原始评估记录（供后续复核）

### 1. 草稿体系与版本安全

| ID | 问题 | 建议 | 验收标准 |
|---|---|---|---|
| P1-1 | 每篇文档仍只有一条草稿，同浏览器多标签/同设备多窗口会静默覆盖 | 改为按“设备 ID + 标签页 ID”保存多份草稿；冲突弹窗展示正文 diff；合并走真正的三方合并 | 两个标签页同时编辑，保存时能看到差异并选择保留/合并；不丢任意一方内容 |
| P1-2 | 恢复草稿前不比较时间，旧草稿可能覆盖新正文 | 同时读取服务端草稿与本地备份，按 `saved_at` 排序；恢复前展示时间、来源、正文预览 | 旧草稿默认不直接恢复；用户能明确选择“使用草稿/保留正文” |
| P1-3 | 没有草稿箱；新建文章的服务端草稿不可见 | 后台增加“草稿箱”：标题、更新时间、设备、来源文章、继续编辑/删除/转文章 | 所有服务器草稿可在 UI 中查看和清理 |
| P1-4 | 没有文章/文档修订历史与回收站 | 新增 `post_revisions` 快照表；删除改软删除；历史版本可对比/回滚 | 误删可恢复；AI 重组、批量覆盖后可回滚 |

|---|---|---|---|
